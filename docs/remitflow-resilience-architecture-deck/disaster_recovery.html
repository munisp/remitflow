Recovery is immutable, cross-region, and testable
RemitFlow treats backup as an executable recovery control: versioned data, verifiable integrity, separate-region recovery capacity, and a drill that refuses unsafe targets.
01 / CAPTURE

Scheduled database backup

A non-overlapping Kubernetes CronJob creates the PostgreSQL backup and a checksum manifest using explicit secret and resource contracts.

02 / RETAIN

Object Lock protection

Encrypted, versioned backup objects carry retention controls so a compromised operator cannot silently rewrite or delete recovery evidence.

03 / REPLICATE

Cross-region verification

The backup runner verifies replica availability and records integrity data for a recovery region rather than assuming the primary storage plane survives.

04 / PROVE

Isolated restore drill

The restore script requires an explicit isolated target, validates the checksum, and refuses production-like destinations before PostgreSQL recovery begins.

OPERATING STANDARD / Promotion requires measured RPO/RTO evidence from a successful isolated restore—not a backup-success log alone.
