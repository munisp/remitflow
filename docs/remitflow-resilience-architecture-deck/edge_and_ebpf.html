Gateway and eBPF layers enforce zero trust
The platform rejects malformed identity at the edge, validates tenant context before service access, and applies workload-level policy with observable evidence rather than permissive network assumptions.
01 / APISIX EDGE
Reject malformed and unsigned bearer tokens before downstream calls.Three-segment token shape, no query token, no credential logging, reviewed CORS, and token-to-tenant claim binding protect the account route.
02 / CILIUM DATA PLANE
Constrain east-west traffic by workload identity.Versioned Cilium policy, WireGuard node encryption, and explicit service-flow rules make the network a policy enforcement point.
03 / HUBBLE EVIDENCE
Make policy verdicts and flow context inspectable.Hubble telemetry and Prometheus alerts identify denied-flow surges and Cilium/Hubble availability loss for rapid investigation.
04 / PROMOTION GATE
Observe first; enable strict default-deny only with evidence.Critical workload labels are prepared, but strict policy requires an approved Hubble audit gate in a live Kubernetes environment.
DEPLOYMENT DISCIPLINE / The repository implements the enforcement controls; cluster rollout remains intentionally staged to prevent unmodeled-service disruption.
