One trace connects edge, service, and policy evidence
Validated W3C trace context gives an investigator a single correlation path from APISIX ingress through application requests, background regulatory work, Cilium/Hubble flows, and Prometheus alerts.
01 / INGRESS

APISIX request ID

Gateway validation captures a bounded correlation identifier without recording bearer credentials.

→
02 / SERVICE

W3C trace context

Application requests and queue lifecycle events emit compatible trace and HTTP metrics.

→
03 / NETWORK

Hubble policy flow

Cilium records workload-to-workload policy verdicts and denied-flow evidence.

→
04 / RESPONSE

Actionable alert

Prometheus detects filing dead letters, queue stalls, policy-drop surges, and backup failures.

INVESTIGATION OUTPUT
Operators can correlate a regulatory delay or denied service path to the ingress request, tenant-scoped workflow, eBPF verdict, and alert—without stitching unrelated logs manually.
